# 极狐媒体同步完善：方案与验收

> 2026-10-16 后续变更：按用户要求删除 ARCFOX Link 回退及路由选择代码。媒体仅通过原车 HIDL 消息 114 直连；不可用时保留状态并按现有节流重试，不发送 Link 广播。本方案以下内容以直连专用版本为准。

范围为 DiPlay 与嘟嘟。保留现有车速、门状态和胎压卡片，不修改导航、HUD、电话、蓝牙连接状态或认证逻辑。

## 职责

DiPlay 持有 iPhone 的真实 NowPlaying／封面及媒体会话。它负责向仪表发布 CarPlay 音乐、向手机转发控制，并在原车音乐接管时暂停手机及停止仪表发布。

嘟嘟观察原车媒体中心当前音源以及 DiPlay 的 Android MediaSession。桌面卡片的曲目、封面、播放状态、进度和控制对象必须使用同一个选定音源。只观察源和转发命令，不伪造原车切源。

原车媒体服务与仪表保持原有职责。DiPlay 使用原车服务已证实的 IFgeComService transaction 1 发送消息 114／mediatype 19，不注册 vendor 客户端，不改变方向盘 serviceId 14 或原生 CarPlay 连接标志。静态依据见 ARCFOX_MEDIA_DIRECT_TRANSPORT_AUDIT_20261016.md。

## 五项实现

1. 进度：单调时钟外推，暂停冻结，歌曲变化／跳转重新定位，时长封顶。常规进度每秒至多一次；状态 10 秒补发。
2. 封面：原生直连每包引用自有缓存文件名，只在需要时写文件；文件用内容哈希命名、原子替换、仅清理自身旧文件。不发送 Link 封面广播；写图失败不阻断歌曲文字及进度。
3. 恢复：后台串行发送、失败后重试并重取失效 HIDL 句柄；只调用原车 HIDL，不选择其他转发通路。无远端绘制确认，不把 HIDL 返回说成仪表已显示。所有权恢复重发完整快照；失去源和断开取消周期发布。
4. 音源：真实新播放或原车明确源变更才改变所有权。进度和元数据回调不得抢回。失去原车媒体源后不发空歌曲覆盖新来源。
5. 嘟嘟：按同一 source 过滤 metadata／state／progress，控制同一 source；session 销毁和服务重绑恢复。确认原车接管时，可发签名权限保护、包限定、10秒有效的本机通知给 DiPlay，补齐无 Android MediaSession 的原车来源。DiPlay 经焦点／媒体会话确认让出时，也发送相同签名保护的 YIELDED 通知给嘟嘟，补齐 SDK source/state 不变但手机已暂停的情况；重复或过期包丢弃，不互相回发。

## 验收

- 单元／离线边界：进度、seek、暂停、封面晚到、错误轮次、源让出和重获、服务不可用及恢复、HIDL结构和缓存文件安全。
- 嘟嘟：当前源过滤、播放状态枚举、命令源、session销毁、重绑、原车切源优先、重复进度不能抢源，原有车况／胎压新增 dex 保留。
- 完整仓库 CI 使用 AGENTS.md 的命令；两包均用用户 platform 证书签名并校验。原有认证素材逐字节保持。
- 车辆未连接：物理仪表显示、车机 SELinux 对 HIDL／封面目录的权限、原车源切换时序及方向盘实机行为列为实车验收，不用离线通过代替。

直连绕过原仪表服务栈登记，因此增加发布门控：仅系统音频模式 NORMAL 且没有当前 CarPlay 电话时使用直连。非普通模式挂起发送，恢复 NORMAL 后继续直连。没有增加电话状态写入或蓝牙控制。

嘟嘟原车媒体插件原 UI 名称为“QQ音乐”，实际控制器 101 对应 com.arcfox.media。CarPlay 的真实新播放边沿可按原有机制切到该控制器，使卡片与按键一致；不会因 metadata/progress 或重绑快照切换。手机会话消失且原车未接管播放时恢复此前播放器。具体补丁与离线测试见 tools/arcfox-media/README.md。
